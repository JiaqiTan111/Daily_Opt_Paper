核心洞察

贡献有效性来自一个关键判断：真正可迁移的不是单次解或参数，而是分布层面的结构假设与由此合成的专用求解代码。因为通用搜索被替换为针对分布结构的更小计算，运行时大幅下降；而 LLM 只在部署前做假设提出、训练实例分析和代码合成，避免了部署期的模型推理开销，使专用化的离线成本可以被重复部署中的运行节省所摊销。

为什么值得看：该工作为学习辅助求解提供了与强化学习、图神经网络互补的思路：不直接学习策略或值函数，而是用 LLM 在离线阶段合成专用求解代码。其样本访问插值分析与离线/在线成本权衡，对关注公平计算预算、泛化和可复现性的生产调度研究者具有直接参考价值，特别是需要反复求解同一分布实例的场景；同时它在 PACE 竞赛上的运行时对比提供了一个较清晰的专用化收益边界。

研究设定
研究问题是在同一未知部署分布下反复求解同类优化问题时，如何利用历史实例经验生成比通用求解器更廉价的可执行求解器代码；决策对象是求解器代码本身（结构假设与专用算法），目标是在保证解质量与运行时对新实例泛化的前提下降低部署期计算开销，关键约束包括只能访问分布样本、LLM仅在部署前使用、代码质量与运行时需泛化到未见实例；环境为静态离线训练加在线部署的设定，部署分布未知。材料未说明是否涉及动态扰动、多目标或具体生产场景。
研究动机
许多优化问题被反复求解，实例来自同一底层分布，通用求解器每次都从头搜索，忽略了分布中可复用的结构规律；作者希望把这种从经验中学习专用求解方式的直觉形式化，并回答样本访问如何插值于分布无关与分布感知的算法设计之间、离线专用化的代价何时能通过更低的部署成本回收。
核心洞察
贡献有效性来自一个关键判断：真正可迁移的不是单次解或参数，而是分布层面的结构假设与由此合成的专用求解代码。因为通用搜索被替换为针对分布结构的更小计算，运行时大幅下降；而 LLM 只在部署前做假设提出、训练实例分析和代码合成，避免了部署期的模型推理开销，使专用化的离线成本可以被重复部署中的运行节省所摊销。
技术挑战
  • 部署分布未知，只能通过样本近似，需要样本量到算法质量的插值分析
  • 生成的求解器代码必须在未见实例上同时保证解质量与运行时泛化
  • 需界定离线专用化开销何时被部署期节省回收
  • 在多个结构不同的组合优化分布上同时保持高质量与低运行时
  • 与专用竞赛求解器对比时需在更少运行时下保持竞争力
问题分析
作者以分布感知编程的形式化框架分析问题，将样本访问视为在分布无关算法设计与分布知情算法设计之间的插值，并给出离线专用化成本被部署期更低成本回收的条件分析；方法层面通过 LLM 智能体提出结构假设、分析训练实例并合成专用求解代码来实例化该框架，材料未说明更细的问题结构分解、下界或图表示利用方式。
方法
  • 形式化分布感知编程：从同一未知部署分布抽取样本，产出可执行求解器代码，其质量与运行时需泛化到新实例
  • 给出样本访问如何在分布无关与分布知情算法设计之间插值的分析，并刻画离线专用化成本何时被部署期更低成本回收
  • 用一个 LLM 智能体实例化框架：提出结构假设、分析训练实例、合成专用求解器代码
  • LLM 仅在部署前使用，部署期执行的是合成出的专用求解器代码，而非 LLM 推理
实验
  • 在 21 个结构化的组合优化分布上，合成的求解器取得高质量，并常常用更小的分布专用计算替代通用搜索或优化
  • 与公开的 PACE 竞赛求解器相比保持竞争力，同时运行时显著更少：PACE 2025 Dominating Set 上少 75–125 倍，Hitting Set 上少 80–96 倍，PACE 2024 OCM 精确赛道少超过 34,000 倍
