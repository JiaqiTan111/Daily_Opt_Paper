研究设定
论文研究黑箱优化中的在线自动化算法设计问题：决策对象是在优化过程每一阶段由大语言模型智能体合成的新可执行算法，目标是在给定评估预算下最大化终端效用（搜索性能），关键约束是保持解的可行性与预算限制（材料未说明具体约束处理机制），信息假设是优化状态 s_t 可充分概括已评估解、近期进展和剩余预算等历史信息并满足马尔可夫性，环境为单目标、维度最高 30 的静态黑箱优化场景（材料未说明动态扰动或分布式约束）。
研究动机
现有基于大语言模型的自动化算法设计大多采用离线范式，算法设计与目标优化在时间上分离，部署后算法固定不变；而传统自适应优化器虽能响应优化状态变化，其调整仅限于预定义的参数、算子或策略，无法改变底层算法逻辑。因此在优化状态动态演化时，固定部署的算法可能不再适配，需要将算法本身视为状态依赖的决策变量，在目标优化运行中在线合成新算法。
核心洞察
论文的核心洞察在于：算法设计不应是一次性的离线产物，而应作为优化过程中随状态变化而在线更新的决策变量。其有效性来源于将程序合成嵌入目标优化回路：执行当前生成的算法既推进搜索又产生反馈，该反馈同时用于下一阶段算法合成和运行时证据解读方式的修正，从而在无需单独离线预训练的情况下，使设计空间超越预定义参数、算子或策略，缓解离线设计范式下设计与执行脱节以及固定算法难以适配状态演化的问题。
技术挑战
  • 在线合成可执行算法并保证其行为逻辑的新颖性与有效性
  • 多智能体设计视角之间的冲突需要协调
  • 运行时证据的解释方式需随执行反馈迭代修正
  • 在不引入额外离线预训练预算的前提下耦合设计与优化
  • 单目标、低维度设定向大规模、噪声、约束和多目标场景推广
问题分析
作者将目标优化与元层算法设计形式化为两个耦合的序贯决策过程，目标优化被建模为马尔可夫决策过程，状态 s_t 概括已评估解、近期进展与剩余预算，动作 a_t 给出下一步候选解，且假设 s_t 充分概括相关历史。在此框架下，算法 π 被表示为状态到动作的映射，在线设计则在每阶段根据 s_t 合成新算法。作者还通过附录中的性能差分析给出命题 1，用设计空间误差、表示误差和合成误差上界刻画 OnDesign 与理想在线设计器之间的期望终端效用差，并据此将 State Analysis 和 SAG Evolution 对应到当前与后续状态表示的决策相关信息，将 Multi-Agent Deliberation 对应到算法覆盖与合成。
方法
  • 将目标优化与算法设计视为耦合的序贯决策过程，状态 s_t 包含已评估解、近期进展与剩余评估预算，动作 a_t 指定下一步候选解，算法被表示为由状态到动作的映射。
  • 提出在线 LLM 基 AAD 范式：在每一阶段由 LLM 智能体从当前优化状态合成具有新行为逻辑的算法，执行该算法推进搜索并产生反馈，用于后续设计，无需单独离线算法预训练。
  • 提出 OnDesign 多智能体框架，包含 State Analysis、Multi-Agent Deliberation 和 SAG Evolution 三个模块。
  • State Analysis 负责从当前优化状态中提取决策相关信息；Multi-Agent Deliberation 协调相互竞争的设计视角以合成可执行算法；SAG Evolution 利用执行反馈修正运行时证据的解读方式，并影响后续算法合成。
  • 执行反馈同时用于两部分：生成后续算法，以及更新用于解释运行时证据的指导准则。
实验
  • 在两个主流黑箱优化范式、三个场景上进行评估：贝叶斯优化、进化连续优化、进化混合变量优化。
  • 在六个基准测试套件和一个工程问题上、跨多个问题维度进行实验。
  • 结果表明 OnDesign 在整体性能上优于传统优化器和离线 LLM 基 AAD 方法。
  • 消融实验显示，在 D=30 维度下移除任一模块都会使平均排名变差，说明三个模块具有互补作用。
  • 材料未提供具体基线名称之外的数值结果、运行时间、训练开销或公平计算预算细节。
局限
  • 当前评估聚焦于单目标问题且决策变量最多 30 个，向大规模、噪声、约束和多目标场景的适用性仍需进一步研究。
  • 未来工作将把评估扩展到这些场景。
与你的研究关系
该论文与智能优化和 AI4OR 中“学习辅助搜索/算法自动设计”方向直接相关，其核心是把算法本身作为在线决策变量，由 LLM 智能体根据优化状态合成新可执行算法，并以执行反馈驱动后续设计。这与研究画像中关注的神经网络辅助求解、强化学习/多智能体优化、学习与搜索结合等机制有明确的概念联系；但该论文面向的是通用黑箱优化（贝叶斯优化、连续与混合变量进化优化），并未涉及柔性作业车间、流水车间、分布式制造、生产运输协同或动态扰动等具体生产调度问题。推测若要迁移到生产调度，需要将优化状态替换为调度状态表示（如机器、工序、运输资源、扰动事件与剩余计算预算），并设计可执行的调度算子或求解策略合成模板，同时验证约束可行性、解质量和公平计算预算下的泛化能力；这些迁移路径属于推测，并非作者结论。
