VeriSimpl：基于简化验证的自然语言鲁棒优化建模

VeriSimpl: Robust Optimization Modeling from Natural Language using Simplification-based Verification

Sumaya Abdul Rahman · Seckhen Ariel Andrade Cuellar · Ghani Raissov · Mohammad Raza

核心洞察

与其让 LLM 提出测试场景再由求解器检查，不如反向利用求解器在高维空间中构造可行/最优解的可靠性，主动生成降复杂度的诊断查询，使 LLM 能在固定全局上下文下进行局部推理，从而以可处理的方式判断候选公式相对于任务描述的正确性；这种角色反转使得验证既保留全局语义结构，又降低 LLM 的推理负担，因此比单纯代码生成或 prompt 工程更稳健。

为什么值得看：该论文针对 AI4OR 中关键且真实存在的痛点——LLM 生成的优化公式可执行却语义错误——提出了求解器反向构造诊断查询的自验证框架，并在多个基准上给出一致的精度提升与高精度自验证信号。对研究生产调度自动建模、约束可行性验证和求解器-LLM 协同的研究者而言，其约束/变量维度分解与局部化推理思路可直接启发如何对调度模型中的工序约束、机器容量约束与决策变量语义进行系统化验证。

研究设定
研究问题是将自然语言描述的优化问题自动翻译为可由求解器执行的 MILP 形式化代码；决策对象是候选求解器程序（solver code）的选取；目标是提高翻译正确率并提供高精度的自验证信号；关键约束在于优化程序正确性依赖决策变量、约束与目标之间的全局交互，传统单元测试/行为测试用例方法不可行；信息假设为给定自然语言问题描述及数据 (x,d)，并可调用 LLM 与优化求解器；环境为静态离线基准评估，非动态在线调度场景。
研究动机
优化建模对非专家用户门槛高，需要运筹学与求解器 API 双重专业知识；LLM 虽可将自然语言转为求解器代码，但生成的公式即便能无错误执行，也可能因细微语义错误而错误地实现了任务。由于正确性取决于全局交互，用测试实例检测错误本身就是一个高维困难优化问题，因此需要新的验证范式。
核心洞察
与其让 LLM 提出测试场景再由求解器检查，不如反向利用求解器在高维空间中构造可行/最优解的可靠性，主动生成降复杂度的诊断查询，使 LLM 能在固定全局上下文下进行局部推理，从而以可处理的方式判断候选公式相对于任务描述的正确性；这种角色反转使得验证既保留全局语义结构，又降低 LLM 的推理负担，因此比单纯代码生成或 prompt 工程更稳健。
技术挑战
  • 候选公式可执行但语义错误，细微错误难以检测
  • 优化代码正确性依赖变量、约束、目标的全局交互，传统单元测试不可行
  • 在高维空间生成满足可行性或最优性条件的可靠测试实例本身是困难优化问题
  • LLM 与求解器可能共享对变量（如 start time）的错误解释，导致验证通过但模型整体错误
  • 简化查询无法覆盖被候选程序完全遗漏而非错误表述的自然语言要素
问题分析
作者从优化问题的结构出发，将候选程序分解为约束维度与决策变量维度，对每个约束构造规范化形式 e(V)≤0 并生成三种变异（严格小于、等于、严格大于）以探测可行性与最优性属性；通过在固定全局上下文下改变局部约束或变量取值，将全局正确性判断分解为可局部推理的子问题，并聚合多个验证信号进行候选程序排序。
方法
  • 给定自然语言描述与数据 (x,d)，从语言模型采样 K 个候选程序（实验中 K 最多为 10）
  • 对每个候选程序执行三类验证：约束验证、变量验证和类型验证
  • 约束简化验证：对每个约束规范化并构造三种变异（≤-δ、=0、≥+δ），由求解器生成 witness valuations，形成可行性诊断查询交由 LLM 推理
  • 变量简化验证：分为单变量验证与全变量验证，分别探测决策变量的语义解释
  • 类型验证：作为语法一致性检查
  • 生成四个归一化分数：约束验证 sc、单变量验证 sd、全变量验证 sf、类型验证 st
  • 三个语义验证信号等权聚合为最终语义验证分数，类型验证仅通过字典序作为二级打破平局信号，优先语义正确性
  • 按综合得分选取排序最高的公式提交最终求解
  • 在全部验证查询成功时输出自验证信号，作为系统置信度指标
实验
  • 在四个基准数据集（NL4Opt、NLP4LP、CompOR、IndOR）上评估
  • 与 BaseLLM、SelfDebug、Optimus 等基线比较，VeriSimpl 在所有基准上表现最佳
  • 使用 GPT-4o 与 DeepSeek-R1 两种 LLM：NL4Opt 上 VeriSimpl 取得 88.1（GPT-4o）与 88.5（R1），缩小了基础模型之间 75.5 与 78.4 的差距
  • 报告了数据集规模加权平均准确率，VeriSimpl 仍为最佳，相对 SelfDebug 与 BaseLLM 提升更大
  • Optimus 在加权平均下因在较大的 NL4Opt 上表现较好而显著上升，但仍低于 VeriSimpl 与 SelfDebug
  • 自验证精度与覆盖率（Table 4）：GPT-4o 下平均精度 91.5、覆盖率 34.2；R1 下平均精度 78.5、覆盖率 23.0；NL4Opt 上 GPT-4o 精度 92.7、覆盖率 32.1，R1 精度 95.7、覆盖率 38.2；CompOR 上 GPT-4o 精度 100.0、覆盖率 53.8，R1 精度 66.7、覆盖率 15.3；NLP4LP 上 GPT-4o 精度 90.0、覆盖率 28.1，R1 精度 75.0、覆盖率 17.1；IndOR 上 GPT-4o 精度 83.3、覆盖率 22.7，R1 精度 76.5、覆盖率 21.3
  • 还报告了使用 Mistral large 模型的评估显示类似结果
  • 运行时间、训练开销、实例规模、约束可行性的详细量化指标：材料未说明
局限
  • 决策变量被假定为给定，并在 LLM 推理与求解器分析之间共享，未显式验证变量定义
  • 简化查询无法覆盖被候选程序完全遗漏或忽略的自然语言描述要素，缺少面向覆盖的检查
  • 当 LLM 与求解器共享同一错误解释时，模型内部一致且验证通过，但整体错误
与你的研究关系
论文事实：该工作研究 LLM 驱动的自然语言到 MILP 求解器代码的形式化，并用 solver-in-the-loop 生成诊断查询进行自验证，属于 AI4OR 中的自动建模与学习辅助求解方向。迁移设想（推测）：其简化验证机制可迁移到生产调度问题的自然语言/结构化建模流程中，例如柔性作业车间或分布式制造场景中由领域人员描述约束、系统生成 MILP 模型，再用约束维度和变量维度的简化查询验证生成的工序、机器分配与运输约束是否正确；迁移需具备的条件是：目标调度问题能被规范化表达为约束集合与决策变量集合、求解器可稳定生成可行 witness、且验证查询能在固定全局上下文下局部化，否则对时间耦合强、动态扰动频繁的调度问题可能不完全适用。
证据与不确定性

输入材料为摘要与部分全文节选，缺少完整的实验设置细节（如实例规模、运行时间、训练开销、公平计算预算比较、完整消融），部分方法描述在节选处被截断（如 OPEN Mutate 的完整定义），因此对方法细节和实验全面性的判断存在不确定性；相关性评分基于其自动建模与求解器-LLM 协同对 AI4OR 的可迁移性，而非论文直接针对车间调度问题。

论文提出基于简化验证的求解器-LLM 框架，用求解器生成关于候选公式的简化诊断查询，使 LLM 能可处理地推理公式正确性：Our approach is based on the idea of simplification-based verification, where the optimization solver is leveraged to generate simplified diagnostic queries about a candidate formulation to allow the LLM to tractably reason about the correctness of the formulation with respect to the task description.
作者指出即便生成的求解器代码可无错误执行，仍可能没有正确实现意图任务，这是核心挑战：However, a key challenge remains: even when an LLM-based system produces solver code that may execute without errors, the generated formulation may not correctly formulate the intended pr
作者反转传统验证流程，用求解器构造降复杂度实例，而非让 LLM 提出测试场景：instead of using the LLM to propose test scenarios that are then checked by the solver, we leverage the solver’s reliability in constructing feasible and optimal solutions in high-dimensional space to obtain reduced-complexity problem instances that are tractable for reasoning by the LLM.
方法采样 K 个候选程序，进行约束、变量与类型三类验证，产生四个归一化分数，语义分数等权聚合，类型验证仅作平局打破：The three semantic verification signals are aggregated using equal weighting to produce the final semantic verification score, while type verification is used only as a secondary tie-breaking signal through lexicographic ordering (thus we prioritize semantic correctness over syntactic consistency).
作者明确承认的局限包括决策变量被假定为给定且共享、验证不覆盖被完全遗漏的描述要素：decision variables are assumed as given and shared between the llm reasoning and solver analysis, and simplification queries do not cover any aspects of the NL description that may be completely missed or ignored by the candidate program rather than incorrectly formulated.
