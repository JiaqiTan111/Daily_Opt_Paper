分区分数不是系统分数：分解式算法选择中的部署保真度差距

Partition Scores Are Not System Scores: Deployment-Fidelity Gaps in Decomposed Algorithm Selection

Jiachen Zhang · Yu Tang · Li Zhu

核心洞察

作者指出分区级分数与可部署端到端分数之间存在结构性偏差，其根源在于分区评估阶段隐藏了族内选择的学习误差；通过定义部署保真度差距 G(R)，作者把该偏差形式化为分区级效用与可部署端到端效用之差，并给出两个核算后果：一是一个逐实例的 margin-regret 稳定性条件，用于判断分区阶段的族选择在部署时是否最优；二是一个紧的分区-only 识别区间，当该区间严格跨越零点时，分区级报告无法认证可部署胜者。

为什么值得看：论文揭示了分解式算法选择中分区级评估与端到端部署效用之间的系统性偏差，并给出可操作的核算条件与修正诊断。对于研究学习辅助搜索、求解器选择与智能优化系统的博士生而言，该工作提醒在报告 oracle 类上界时需区分分区级分数与系统级分数，并提供了识别区间与稳定性条件等分析工具，可迁移到生产调度中求解器组合与算法选择的评估设计。

研究设定
研究问题为分解式算法选择流水线中分区级（partition-level）评估与可部署端到端系统实际效用之间的偏差；决策对象是在固定家族选择器之后，如何在选定算法族内部用学习到的族内选择器替代族内 oracle；目标为量化并修正分区级报告与部署端到端效用之间的差距；关键约束是分区级分数只给出族内最优的 oracle 选择，而可部署系统必须用学习到的选择器替代该 oracle；信息假设为分区级评估可获得族内 oracle 信息，而部署时只能基于学习信号；静态或动态环境材料未说明。
研究动机
oracle 类量（如 virtual best solvers、selected-portfolio VBS、virtual-best encodings、best-in-family summaries）被广泛报告为可部署选择器能达到的上界；在分解式算法选择中，分区级分数等价于在选定族内给予 oracle 最优算法的选择，而一旦族选择器固定，可部署系统必须用学习到的族内选择器替代该 oracle，因此分区级报告可能无法认证可部署的胜者，造成系统性高估。
核心洞察
作者指出分区级分数与可部署端到端分数之间存在结构性偏差，其根源在于分区评估阶段隐藏了族内选择的学习误差；通过定义部署保真度差距 G(R)，作者把该偏差形式化为分区级效用与可部署端到端效用之差，并给出两个核算后果：一是一个逐实例的 margin-regret 稳定性条件，用于判断分区阶段的族选择在部署时是否最优；二是一个紧的分区-only 识别区间，当该区间严格跨越零点时，分区级报告无法认证可部署胜者。
技术挑战
  • 分区级评估中族内 oracle 与可部署学习选择器之间的信息不对称导致系统性高估
  • 需要在不直接进行端到端评估的前提下判断分区阶段族选择是否在部署时最优
  • 跨不同基准（tabular AutoML 与组合 CSP/SAT）的分区级与端到端分数可能出现符号翻转
  • 验证侧差距修正诊断只能恢复点估计符号，不能替代直接端到端评估
问题分析
作者通过定义部署保真度差距 G(R) 将问题形式化，推导出逐实例 margin-regret 稳定性条件以刻画分区阶段族选择在部署时最优的条件，并推导出分区-only 识别区间；当该区间严格跨越零时，分区级报告被证明无法认证可部署胜者。作者进一步从训练侧提出验证差距修正诊断，用于恢复点估计的可部署符号。
方法
  • 定义部署保真度差距 G(R)：分区级效用与可部署端到端效用之差
  • 推导逐实例 margin-regret 稳定性条件，判断分区阶段族选择在部署时是否最优
  • 推导紧的分区-only 识别区间，当区间严格跨越零时阻止分区级报告认证可部署胜者
  • 提出训练侧验证差距修正诊断，用于恢复点估计的可部署符号
实验
  • 在五个公开算法选择基准上评估，覆盖 tabular AutoML 与组合 CSP/SAT
  • 所有分解式流水线均呈现正的 G(R)，范围从 TabZilla 上的 0.012 到 PROTEUS-2014 上的 0.13
  • 十个分解式与扁平式对比决策中有四个出现符号变化的点估计
  • 在 PROTEUS-2014 上，33 个百分点的分区优势缩减为 20 个百分点的端到端优势
  • 训练侧验证差距修正诊断在所有四个符号变化单元上恢复了点估计的可部署符号
  • 该诊断被定位为报告辅助工具，不能替代直接端到端评估
  • 材料未说明基线、实例规模、约束可行性、解质量、运行时间、训练开销、公平计算预算、泛化和消融等细节
局限
  • 训练侧验证差距修正诊断是报告辅助工具，不能替代直接端到端评估
  • 作者建议分区与端到端分数应并排报告
与你的研究关系
该论文直接研究算法选择中的评估保真度问题，其核心机制——分区级 oracle 分数与可部署学习选择器之间的差距——可迁移到生产调度与智能优化中的求解器/算法选择场景。论文事实层面，作者在五个公开算法选择基准上验证了正 G(R) 与符号翻转现象；迁移设想层面（推测），若将分解式算法选择框架用于柔性作业车间或流水车间的求解器选择，需要满足以下条件：分区级评估可用、族内选择器可学习、且能获得端到端部署效用的评估预算。该工作对关注学习辅助搜索与算法选择的调度研究者具有方法学参考价值，但论文本身未涉及生产调度实例。
